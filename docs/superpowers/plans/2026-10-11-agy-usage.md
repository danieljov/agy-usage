# agy-usage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Rust CLI `agy-usage` that samples Antigravity quota every 5 minutes and shows per-bucket history, budget line and burn-rate prognosis in a ratatui TUI and a self-contained HTML dashboard.

**Architecture:** Library crate with pure modules (`model`, `source`, `store`, `forecast`, `html`, `tui`, `timer`) and a thin `clap` binary. All forecasting is pure and deterministic (anchored at the latest sample, not wall-clock). A systemd user timer runs `agy-usage collect`.

**Tech Stack:** Rust 1.99 (edition 2024), `anyhow`, `chrono` (serde), `clap` (derive), `serde`, `serde_json`, `ratatui` (crossterm backend); dev: `tempfile`. Chart.js 4 + `chartjs-adapter-date-fns` via jsDelivr CDN in HTML.

**Spec:** `docs/superpowers/specs/2026-10-11-agy-usage-design.md`

## Global Constraints

- Crate root: `agy-usage/` inside the repo; binary name `agy-usage`.
- Data source: `agy -p "/usage" --output-format json`; read only `command.data.groups[].buckets[]`.
- Group/bucket names come from JSON; never hard-coded.
- Window lengths: `weekly` = 7 days, `5h` = 5 hours; unknown window → no budget line, no lookback (use whole current window).
- Lookback for burn rate: weekly 24 h, 5h 1 h. Minimum: ≥ 2 samples spanning ≥ 15 min.
- Window boundary thresholds: reset moved forward > 60 s, remaining rose > 0.005.
- Default tight threshold `0.10`; default data dir `$XDG_DATA_HOME/agy-usage` else `~/.local/share/agy-usage`.
- Files: `samples.jsonl`, `dashboard.html` in the data dir. Timestamps stored UTC, displayed local.
- Timer: every 5 min, `Persistent=true`, units `~/.config/systemd/user/agy-usage.{service,timer}`.
- Gate: `cargo test`, `cargo clippy --all-targets -- -D warnings`, `cargo fmt --check` all green.
- Rust needs `. "$HOME/.cargo/env"` (or `~/.cargo/bin` on PATH) in every shell.

## Review Focus

1. **Idle 5h bucket at 100 % has a sliding `reset_time` (= now + 5 h on every fetch).** Must not create a new window per sample → boundary-by-reset only counts when the previous sample's `reset_time` ≤ current sample's `ts` (previous window expired). Test in Task 3.
2. **Stale data** (timer stopped; latest `reset_time` already before latest `ts` or long ago): no NaN/negative hours; `safe_rate`/`at_reset` = `None`, status `Collecting`, UI shows sample age. Test in Task 3.
3. **`agy` not on systemd's minimal PATH** (`~/.local/bin`): `install-timer` resolves `agy` to an absolute path and writes `Environment=AGY_BIN=<abs>`; `collect` uses `$AGY_BIN` if set. Test in Task 6.
4. **Group name containing `</script>`** breaking the HTML: embedded JSON escapes `<` as `\u003c`. Test in Task 4.
5. **Tiny terminal / more than 4 buckets**: TUI render must not panic at 20×5 and must lay out N buckets. Tests in Task 5.

### Task 3: Forecast

**Files:**
- Create: `agy-usage/src/forecast.rs`

**Interfaces:**
- Consumes: `Sample`, `window_length`, `lookback`.
- Produces:
  - `enum Status { Collecting, WillRunOut, Tight, OnTrack }` with `fn label(&self) -> &'static str` → `"⏳ collecting"`, `"❌ will run out"`, `"⚠️ tight"`, `"✅ on track"`.
  - `struct Prognosis { remaining_now: f64, reset_time: DateTime<Utc>, last_sample: DateTime<Utc>, budget_now: Option<f64>, rate_per_h: Option<f64>, safe_rate_per_h: Option<f64>, at_reset: Option<f64>, empty_at: Option<DateTime<Utc>>, status: Status }` — fractions 0..1, rates in fraction/hour (UI multiplies by 100).
  - `struct BucketReport { group: String, bucket_id: String, window: String, history: Vec<Sample>, current: Vec<Sample>, window_start: Option<DateTime<Utc>>, boundaries: Vec<DateTime<Utc>>, prognosis: Prognosis }` — derive `Serialize` (used by HTML).
  - `fn window_boundaries(samples: &[Sample]) -> Vec<usize>` — indices *i* where a new window starts (sorted input, one bucket).
  - `fn prognose(current: &[Sample], tight: f64) -> Prognosis` — `current` non-empty, sorted.
  - `fn analyze(samples: &[Sample], tight: f64) -> Vec<BucketReport>` — groups by `(group, bucket_id)`, sorts by `ts`; order: groups by first appearance in the **latest** `ts` batch (then older groups), within a group `weekly`, `5h`, then others alphabetically.

Rules (anchor `t0 = last_sample.ts`, `r0 = last.remaining`, `end = last.reset_time`, `L = window_length`):
- Boundary at *i* if `remaining[i] > remaining[i-1] + 0.005`, or (`reset_time[i] > reset_time[i-1] + 60 s` **and** `reset_time[i-1] <= ts[i]`).
- `window_start = end − L`; `hours_left = (end − t0)` in hours.
- If `hours_left <= 0` (stale) → `budget_now`, `safe_rate`, `at_reset`, `rate` = `None`, status `Collecting`.
- `budget_now = hours_left / L_hours`; `safe_rate = r0 / hours_left`.
- Rate: samples in `current` with `ts >= t0 − lookback`; need ≥ 2 and span ≥ 15 min, else `Collecting` (rate/at_reset/empty_at `None`). Least-squares slope of remaining vs hours; `rate = max(0, −slope)`.
- `at_reset = max(0, r0 − rate·hours_left)`; `empty_at = t0 + r0/rate` if `rate > 0` and `< end`.
- Status: `empty_at.is_some()` → WillRunOut; `at_reset < tight` → Tight; else OnTrack.

  - `runs_out_before_reset`: 0.50→0.30 over 60 min → `rate ≈ 0.2`, `empty_at ≈ t0 + 1.5 h`, `at_reset == 0`, `WillRunOut`.
  - `tight_boundary`: `r0=0.50`, `hours_left=4.0`; series with `rate ≈ 0.09975` → `at_reset ≈ 0.101` → `OnTrack`; `rate ≈ 0.10025` → `at_reset ≈ 0.099` → `Tight` (avoid exact 0.10 float equality).

### Task 4: HTML dashboard

**Interfaces:**
- Consumes: `forecast::BucketReport`.
- Produces: `html::render(reports: &[BucketReport], generated_at: DateTime<Utc>) -> String`.

Template (`include_str!`) contains the literal `/*__AGY_DATA__*/null` which is replaced with `{"generated_at":…, "reports":[…]}` from `serde_json::to_string`, then every `<` replaced by `\u003c`. Page JS:
- one `<canvas class="bucket-chart" data-idx="N">` per report, created dynamically in a CSS grid (2 columns ≥ 900 px) titled `"<group> · Weekly|5h"`;
- datasets: actual (`history`, solid), budget (`window_start`→100 %, `reset_time`→0 %, grey), projection (last sample → `empty_at` or `reset_time`, dashed red); window boundaries as light vertical lines (plain Chart.js plugin, no extra dependency); time x-axis local time, y 0–100 %;
- prognosis table: Bucket, Left, Rate/h, Budget/h(safe), At reset, Status, Last sample;
- empty state text: `No samples yet — run "agy-usage install-timer" or "agy-usage collect".`
- Scripts: `https://cdn.jsdelivr.net/npm/chart.js@4` and `https://cdn.jsdelivr.net/npm/chartjs-adapter-date-fns@3`.
